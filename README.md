# NOMA

Интерактивные 3D-презентации архитектуры и недвижимости. Открываются по обычной
ссылке в браузере — без установки приложения.

Репозиторий — статический сайт для GitHub Pages: без сборки, без сервера, без базы
данных. Вся логика в `index.html` и модуле `src/tour-io.js`.

---

## Быстрый старт

Проект нельзя открыть двойным кликом по `index.html` — браузер заблокирует
загрузку модели через `file://`. Нужен локальный сервер:

```bash
python3 -m http.server 8765
```

Затем открыть:

| Что | Адрес |
|---|---|
| Редактор (чистый лист) | http://localhost:8765/ |
| Редактор существующего тура | http://localhost:8765/?tour=room&edit |
| Тур глазами клиента | http://localhost:8765/?tour=room |
| Режим презентации | http://localhost:8765/?tour=room&mode=present |

### Режимы

- **`?tour=ID`** — клиентский режим. Интерфейс автора скрыт, остаётся осмотр,
  карточки, экскурсия, заявка.
- **`?mode=present`** — то же плюс чистая обложка: панель бренда без подложки,
  минимум элементов. Для показа клиенту и для ссылок в рассылке.
- **`?edit`** — редактор. Требует пароль, если в `tour.json` задано поле `lock`.
- **Без параметров** — полный редактор с нуля.

## Как создать и опубликовать презентацию

Публикация ручная. Кнопки «опубликовать» нет и она не появится без backend.

1. Открыть редактор, загрузить модель `.glb` (или `.gltf` вместе с `.bin` и текстурами).
2. Расставить точки интереса: нажать на модель, заполнить карточку, задать ракурс.
3. Настроить обложку, название, контакты во вкладке оформления.
4. Нажать **«Скачать tour.json»**.
5. Положить файл в `tours/<id>/` рядом с моделью, обложкой и PDF.
6. Закоммитить и запушить в ветку `main` — GitHub Pages обновит сайт.
7. Ссылка для клиента: `https://<домен>/?tour=<id>&mode=present`

### Структура папки тура

```
tours/mytour/
  tour.json        обязателен
  scene.glb        модель, имя из поля model
  cover.jpg        обложка (необязательно, 1920×1080, до ~500 КБ)
  plan-1.pdf       планировки (необязательно)
  photos/1.jpg     фотографии для карточек (необязательно)
```

Все пути в `tour.json` — **относительно папки тура**. Абсолютные `https://` тоже
работают.

## Формат tour.json

Полное описание полей, примеры и правила — в [`docs/tour-schema.md`](docs/tour-schema.md).

Коротко: старые туры (`noma: 1`, `scene.version: 1`) читаются как есть. Новые поля
необязательные — `scene.groups`, `docs`, `group`.

## Тесты

```bash
# Юнит-тесты нормализации tour.json (без браузера, Node 18+)
node tests/tour-io.test.mjs

# Браузерные smoke-тесты (нужен запущенный сервер на :8765)
pip install playwright
python3 -m playwright install chromium
python3 -m playwright install-deps chromium
python3 tests/smoke.py
```

Тесты проверяют реальные сценарии: загрузку туров, скрытие инструментов автора,
открытие карточки, запуск экскурсии, устойчивость к битым данным, отклонение
опасных URL, работу рендера по требованию.

Их можно запускать локально. В CI они не настроены.

## Что реализовано и проверено

Проверено автотестами в headless Chromium:

- загрузка существующих туров, обратная совместимость формата;
- клиентский режим: инструменты автора не отображаются;
- карточка точки интереса открывается, галерея без фото показывает заглушку;
- экскурсия с гидом запускается и останавливается;
- битая точка в `tour.json` пропускается, тур открывается;
- понятное сообщение при отсутствующей модели;
- `javascript:` и `data:text/html` отклоняются;
- рендер по требованию: в покое кадры не рисуются, при движении камеры — рисуются;
- в редакторе рендер остаётся непрерывным.

- зоны: тяжёлая модель корпуса подгружается по выбору и выгружается при возврате
  (проверено по счётчикам геометрии и draw call);
- кнопки анимации: читаются из `scene.triggers`, рисуются точками в орбите,
  проявляются по близости в пешеходе, запускают клип, сохраняются в JSON;
- камера: приземление в пешеходе над полом, выход в орбиту на ~3 м выше пола
  под углом ~45°, клик по пину
  не выбивает из пешехода, перекрытые пины скрыты, двойной клик меняет точку
  вращения без потери приближения, объекты в упоре не отсекаются (near = 0.005).

**Не проверено:** iOS Safari, Android Chrome, реальные видеокарты, сенсорные жесты,
производительность на слабых устройствах, внешний вид глазами (проверялись
координаты элементов, а не скриншоты). Всё тестирование шло в headless Chromium
с программным рендерингом (SwiftShader).

Замеры производительности на реальном железе не проводились. Счётчики кадров
в headless нестабильны, поэтому тест проверяет состояние гейта рендера, а не
экономию кадров.

## Известные ограничения

- **Публикация только ручная.** Кнопка «скачать tour.json» и коммит в репозиторий.
- **Пароль редактора — не защита.** В `tour.json` лежит SHA-256 от пароля без соли,
  проверка на клиенте. Модели и данные доступны по прямой ссылке всем. Для
  настоящей защиты нужен сервер.
- **Группы (корпуса) нельзя задать в редакторе.** Поле `scene.groups` добавляется
  в `tour.json` вручную. Селектор в клиентском режиме работает.
- **Кнопки анимации не имеют карточки** — это только триггеры клипов. Подписи
  задаются в `tour.json` полем `label`, в редакторе их пока нет.
- **Заявки идут через Web3Forms** — сторонний сервис, до 250 заявок в месяц на
  бесплатном тарифе. Для РФ возможны проблемы с доступностью. Замена на свой
  сервер — отдельная задача.
- **Зависимости грузятся с CDN** (jsdelivr, jspm). При блокировке сайт не
  откроется. Самохостинг — отдельная задача.
- **Нет Service Worker** — офлайн-режима нет.
- **Большие сцены требуют подготовки.** Файл целиком читается в память. Для сцен
  крупнее ~100–150 МБ нужна разбивка на зоны — см. `docs/optimization.md`.

## Зоны и большие сцены

Если сцена тяжёлая, детализацию выносят в отдельные GLB и подключают через
`groups[].model`. Модель зоны грузится при выборе корпуса и выгружается при
переходе на другой — в памяти остаётся одна зона, а не все сразу.

Подробный пайплайн (что делать в Blender, как сжимать, какие цифры считать
нормой) — в [`docs/optimization.md`](docs/optimization.md).

Проверить свою сцену:

```bash
node tools/glb-report.mjs путь/к/сцене.glb
```

Посмотреть, что реально уходит на GPU в браузере:

```js
window.__nomaDebug.stats()
```

`index.html` намеренно остаётся одним файлом: сборщика нет, GitHub Pages отдаёт
статические файлы. Модуль `tour-io.js` вынесен, потому что это чистые функции без
побочных эффектов — их можно тестировать отдельно.

## Безопасность

Перед публикацией тура с реальными контактами проверьте: `tours/*/tour.json` лежит
в публичном репозитории. Почта, телефон и ключ Web3Forms там видны всем. Если это
нежелательно — используйте отдельные ключи для каждого клиента.

Проверка URL централизована в `src/tour-io.js`: разрешены `http`, `https`, `tel`,
`mailto`, `tg`, `whatsapp`, `viber`, `blob`, и `data:image/*`. Всё остальное,
включая `javascript:` и `data:text/html`, отклоняется.
